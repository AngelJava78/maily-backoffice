# Tasks: Administración de Usuarios y Roles de Sistema

**Input**: Design documents from `/specs/002-manage-users/`

**Prerequisites**: plan.md, spec.md, research.md, data-model.md, contracts/, quickstart.md y `.specify/memory/constitution.md`

**Tests**: Incluidas. La plantilla las marca como opcionales, pero la constitución (VII) exige pruebas automatizadas con cada feature y pruebas primero en la lógica pura. Dentro de cada fase, las pruebas se escriben ANTES de la implementación y DEBEN fallar al principio. Se usan Vitest, React Testing Library, user-event y MSW: el servicio de usuarios se simula a nivel de red con el simulador con estado de `src/test/handlers/usersDirectory/` (nunca con un mock de `fetch` ni del cliente HTTP) y Auth0 con el doble centralizado; las pruebas de integración usan `renderApp` (la aplicación completa).

**Organization**: Tareas agrupadas por historia de usuario para poder implementar y probar cada una por separado.

## Format: `[ID] [P?] [Story] Description`

- **[P]**: se puede ejecutar en paralelo (archivos distintos y sin depender de tareas incompletas)
- **[Story]**: historia a la que pertenece la tarea (US1 a US5); solo en las fases de historias
- Cada descripción incluye las rutas exactas de los archivos

## Path Conventions

- **Single project** en la raíz del repositorio (plan.md): `src/`, `e2e/`, `scripts/`
- Código, nombres de archivo y mensajes de commit en inglés; documentación y textos de interfaz en español (los textos de interfaz solo en `src/shared/messages/es.ts`)
- Alias `@/` → `src/`. Dependencias permitidas: `app → features → shared`; una feature solo importa a otra por su `index.ts`. **`src/features/users` NO importa `@/features/auth`** (research D2): las capacidades y el id del operador llegan a las pantallas por propiedades desde los adaptadores de `src/app/router/users/`
- Sin aserciones `as` (salvo `as const`), sin `any`, sin `console.*`; componentes `.tsx` de 250 líneas como máximo (reglas de ESLint)
- Las claves de pruebas y de TanStack Query salen de factorías; las rutas del servicio se aíslan en la capa `api` de la feature
- Los archivos nuevos de `api`, `policy`, `schemas` y `hooks` cuentan para el umbral de cobertura de 80 % (`vite.config.ts`)
